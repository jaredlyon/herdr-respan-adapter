# Cursor Agent

Setup merges version-1 flat `{ "command": "…" }` hook entries into `<CURSOR_CONFIG_DIR>/hooks.json`, defaulting to `~/.cursor/hooks.json` (`USERPROFILE/.cursor` on Windows). `--project` targets `<project>/.cursor/hooks.json`. Existing herdr and user entries retain their order and values. A missing `version: 1` is owned separately; remove deletes it only when this adapter inserted it and it is unchanged. A different existing version is rejected.

Registered events: **postToolUse, postToolUseFailure, afterAgentResponse, stop**. These are observational only. No permission, Tab, prompt-validation, thought, or subagent-start hook is installed. Every invocation returns `{}` before Core gating or any fallible work. A valid unregistered `beforeSubmitPrompt` payload defensively receives `{"continue":true}`; setup never installs it. Grok hook imports are rejected by their environment markers and camelCase envelope, while still receiving the safe reply.

`conversation_id` groups the thread; `generation_id` identifies its turn. Generic post-tool events supply tool ids, inputs, outputs, duration, and errors. The completed response is capped/redacted by Core before being buffered per generation. Stop emits one **generation-summary chat**, then closes the turn. Optional observed `input_tokens`, `output_tokens`, `cache_read_tokens`, and `cache_write_tokens` become usage counters; missing, negative, or invalid counters remain unknown, never zero-filled. Usage is labelled **`cursor.usage_scope = generation`**, not per-provider-request usage. Chat timing is instantaneous at stop: no provider-request latency is claimed. The turn window begins with the first observed completion/post event, not the user prompt. Multiple response callbacks replace the buffer with the latest complete response. Duplicate tool/stop events are deduplicated by the shared assembler.

`model_id` is preferred over the configured `model` slug; `Auto`/`default` remain unresolved (null), and no provider is invented. The configured slug is retained as `cursor.model_slug`. `transcript_path`, when supplied, is passed to Core as `session_path`; no undocumented transcript/SQLite parser or guessed transcript path is used. Session-start is deliberately omitted: observed CLI session-start generation ids match conversation ids, not the first submitted prompt, and would otherwise create orphan turns. Stops without prior callbacks still produce a closed turn and a summary with unknown content/usage. Buffering requires response-before-stop ordering; installed CLI versions without afterAgentResponse still yield tool/turn/optional usage spans but no response text. A missing stop is closed by Core's turn timeout.

No universal minimum CLI version is established. Optional counters were publicly observed on Windows CLI **2026.04.08-a41fba1**; generic hooks and response-event parity vary by installed version. Native Windows command quoting, relocated hook discovery, callback ordering, and real Linux/Windows CLI delivery require installed-agent verification. Cursor provider calls go through Cursor servers; the pass-through proxy is not supported for this agent.

## Fixture provenance

All fixtures are **synthetic**, contain only invented ids/content/paths, and were not captured from an agent run:

- `fixtures/events.json`: common and tool/response fields from [Cursor's official hook reference](https://cursor.com/docs/hooks#reference), retrieved 2026-10-09. Stop counters/common CLI fields from the publicly posted CLI **2026.04.08-a41fba1** schema in [the confirmed Windows duplicate-loading report](https://forum.cursor.com/t/hooks-double-fire-in-windows-cli/157184); only field names/types and illustrative numeric counters are retained, never its personal ids/paths/content.
- `fixtures/stop-batch.json` and `fixtures/tool-batch.json`: expected shared bridge batches for the synthetic stop and tool, using the binding bridge-v1 contract plus approved generation-summary metadata.
- Config root and version-1 flat entries follow [herdr@2563803d `env.rs:182-184`](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/integration/env.rs#L182-L184) and [`targets.rs:1258-1318`](https://github.com/herdrdev/herdr/blob/2563803dca97c040beaf3dc3acdcb5a3221b4238/src/integration/targets.rs#L1258-L1318).

Tests cover fixture-to-batch goldens, shared-assembler span trees, duplicate generations/events, missing usage/model, protocol replies including malformed payloads, Grok/foreign rejection, redacted/metadata-only buffering, and setup/remove/idempotence on temporary herdr-style configs. No providers, Respan endpoints, real agent configs, or logins are used.
