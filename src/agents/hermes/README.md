# Hermes observer adapter

Setup installs `<HERMES_HOME>/plugins/herdr-respan/{plugin.yaml,__init__.py}` and adds the scalar `herdr-respan` to `config.yaml` → `plugins.enabled`. No credentials, provider configuration or Hermes integrations are replaced. Resolution follows herdr: `HERMES_HOME` (including `~/`), otherwise `~/.hermes`; on Windows an explicit differing `HOME` takes precedence, otherwise `%LOCALAPPDATA%/hermes`. The Core-owned binary/state/config paths are embedded as escaped Python literals. Removal deletes only owned assets and our enablement entry.

The YAML `Edit::Text` line editor preserves unrelated comments, inline list-key comments, list order, CRLF and trailing-newline presence. Supported layouts use a plain top-level `plugins:` block mapping, plain mapping keys indented exactly two spaces, and either a single-line scalar `enabled` flow list or scalar block-list entries indented exactly four spaces. Valid YAML with another layout (including four-space `enabled` keys), inconsistent indentation, tabs in indentation, quoted mapping keys, multiline inline values, flow mappings, aliases, legacy flat `plugins` lists and malformed shapes are rejected rather than normalized or rewritten. Config editing is the first setup edit, so unsupported configs fail preview/apply before plugin assets are staged, without changing the config, assets or ownership record. To use setup, manually convert the plugin section to the supported two/four-space layout; setup never does that conversion itself. `plugins.disabled` wins in Hermes: setup warns about a pre-existing disabled `herdr-respan` entry instead of changing that user choice. An already enabled entry remains unowned.

The Python plugin registers only the consumed observer callbacks, returning `None` even on internal errors. Every callback requires `HERDR_ENV=1`, `HERDR_RESPAN!=off`, and `hermes.observer.v1`. Parent turns are admitted only for `cli`, `tui`, `desktop`, or `acp`; Discord/gateway/other messaging platforms are excluded. Tool hooks omit `platform`, so admission follows the native session/turn. Child `platform=subagent` is accepted only after an admitted parent's `subagent_start` establishes the child link.

A lock protects the per-turn memory buffer. `post_llm_call` supplies output; the authoritative `on_session_end` supplies success/interruption/failure and triggers one main handoff for the turn. Late auxiliary events retain the native last-closed session/turn correlation; completed auxiliary chats are batched into a follow-up handoff at the next main handoff or synchronously at interpreter exit, never a subprocess per auxiliary call. A completed parent with live children waits for their stops; sparse shutdown/finalize/reset closes incomplete child lifetimes with error status. Child requests/tools are remapped into the parent turn with their enclosing subagent id. A unique active `delegate_task` hook supplies the spawning tool parent; if native callbacks leave multiple candidate spawning tools, the subagent is honestly parented to the turn instead of guessing.

Handoff serialization, `Popen`, stdin backpressure and process reaping run on a daemon thread outside the buffer lock. The child receives one bridge batch on stdin, with null stdout/stderr, `CREATE_NO_WINDOW` on Windows and a new session on POSIX. Rust alone assigns span keys, applies toggles/redaction/caps, persists and exports. Native chat spans are omitted under `HERDR_RESPAN_PROXY=1` or a Respan base URL.

## Coverage and limits

- Turn spans, per-provider-attempt chat spans (including errors/retries), tool spans and child agent spans.
- Per-request token usage: Hermes `prompt_tokens` becomes total bridge `input_tokens`; uncached/cache-read/cache-write buckets are summed when total is absent. Unknown usage remains null. Cache read/write and reasoning are retained; observer payloads do not expose agent-reported cost.
- Auxiliary calls emit chat spans tagged `hermes.aux_task`, controlled by Core `aux_spans`. The inspected **0.18.0** tower has no auxiliary emitters; registering those hook names is harmless but may produce Hermes' unknown-hook warning. The inspected **0.21.5** Spark has auxiliary emitters. This is a capability difference, not a claim that 0.18.0 emits auxiliary spans.
- Streaming auxiliary observers fire before consumption and lack final content/tokens: those fields remain unknown. Hermes itself sanitizes/bounds native request/response payloads before the plugin sees them; explicit truncation markers are retained. Raw tool results receive Core redaction.
- Pending turns are memory-only until handoff. Abrupt process termination can lose the buffer or daemon handoff. This is not a durable Python spool and does not make a measured callback-latency claim. Minimum native schema verified: Hermes 0.18.0; Python standard library only (3.11+).

## Checks and fixture provenance

`python3 -m unittest discover -s src/agents/hermes -p test_plugin.py` drives registered hooks with synthetic kwargs, compares the exact batch to `fixtures/batch.json`, checks platform/schema gates, platform-less concurrent child tools, absent auxiliary emitters, sparse shutdown, unknown usage, proxy suppression, sanitized request variants, and background/Windows handoff options. `python3 -m py_compile src/agents/hermes/assets/herdr-respan/__init__.py` checks asset syntax; setup substitutes the three placeholder identifiers before import. `cargo test agents::hermes` checks the same batch through the actual shared bridge, resulting span tree, foreign payload rejection and comment-preserving config edits. Setup regressions cover four-space flow/block mappings, already-enabled nonstandard layouts, inconsistent/list/tab indentation and unsupported constructs; failed preview/apply must leave the original config byte-identical and create no plugin assets or ownership record. Unit tests touch disposable directories only. The separate real-agent E2E below uses loopback mocks, never production providers.

`fixtures/hooks.json` and `fixtures/batch.json` are synthetic, not captured live. Schema provenance:

- `NousResearch/hermes-agent@b3bc302370aadeb792ceb0a899cf6a575ed130bb`: `agent/conversation_loop.py:1129-1155,4110-4139` (main request hooks), `run_agent.py:2209-2223,2378-2473` (canonical usage, sanitized bodies and errors), `agent/turn_context.py:433-446`, `agent/turn_finalizer.py:361-379,489-504` (turn boundaries), `hermes_cli/plugins.py:2049-2086`, `model_tools.py:861-903` (tool hooks), `tools/delegate_tool.py:1382-1397,2718-2729` (children).

- Comment-aware line-edit approach: [herdr's config editor](https://github.com/herdrdev/herdr/blob/2563803d/src/integration/config_edit.rs), especially `ensure_hermes_plugin_enabled`/removal; our implementation deliberately refuses unsupported legacy forms instead of treating them as current enablement.

## Real-agent mock-provider E2E

On Spark, build with `~/.cargo/bin/cargo build --release`, then run `bash scripts/e2e/run_hermes.sh`. The driver uses this worktree's release binary (or an explicit `HRA_BIN` override), the existing `~/jare-ai/hermes-agent/venv/bin/python cli.py` runtime, `--provider custom --model mock-model --toolsets terminal --oneshot`, isolated `HERMES_HOME`, HOME/XDG roots and an explicitly constructed credential-free environment. The only inference/OTLP endpoints are the loopback mocks; dummy API keys are used. `HERMES_DISABLE_LAZY_INSTALLS=1` avoids shared-runtime updates. No `~/.hermes` files or gateway service are touched.

Hermes 0.21.5+4905.gf42f579 against herdr 0.9.3 produces two traces: text turn → one main chat + title-generation auxiliary chat; tool turn → main chat + terminal (`echo hra-e2e`) + second main chat + title-generation auxiliary chat. Every chat reports exact mock usage input=11/output=7/cache-read=3. Assertions compare three distinct native `post_api_request` IDs plus two auxiliary observer completions to five delivered chat spans, verify parentage/status/thread IDs/herdr metadata and a single system prompt per request, verify outside-herdr delivery stays unchanged, and require semantic YAML restoration plus removal of owned plugin assets. Native captures, provider requests, OTLP bodies and CLI output remain under `~/.hra-e2e/hermes/run-*`.

`fixtures/live-hooks.json` is **captured live 2026-10-09 against the loopback mock provider**, Hermes `NousResearch/hermes-agent@f42f579cf8bac4918ac9599bece71618afadd846`, first recorded under `run-mjN91FtF`. Native session/turn/database identifiers and isolated paths are scrubbed; system prompt and tool descriptions are replaced with omission markers to keep this fixture focused. Request/response structures, per-request canonical usage, tool echo/result, observer ordering and late auxiliary timing are retained. `test_plugin.py` replays both main turns and late auxiliary callbacks and verifies distinct per-request chats, exact tokens, tool result, nonduplicated system prompt and auxiliary follow-up parenting; a separate regression covers batching multiple late auxiliary events at the next turn's handoff.

The real run exposed and fixed two adapter defects: duplicated system prompts (native body already included them) and discarded auxiliary callbacks arriving after `on_session_end`. This harness does not qualify production authentication, remote providers/Respan, failure/retry behavior, subagents or Windows Hermes; those remain outside its measured stage.
