# Local request proxy

`herdr-respan run <agent> -- <args>` launches an agent with invocation-local endpoint overrides. `run --protocol anthropic|openai|gemini -- <command> <args>` supplies the common SDK environment variables (best-effort for arbitrary commands). The loopback daemon is started only on demand; Tokio's runtime exists only inside `proxy serve`, never in hooks or the launch wrapper. `HERDR_RESPAN=off` launches without interception. Proxy startup failure launches the original command without interception. Cursor mode refuses because its model calls are server-side. Hermes uses its native adapter rather than redundant interception.

No agent setup edits are made by this slice. No key variable, OAuth store, or user config is written. The wrapper sets `HERDR_RESPAN_RUN_ID` and sets `HERDR_RESPAN_PROXY=1` only when model traffic is actually routed through the proxy. In particular, subscription Copilot uses its native metadata-only OTel file exporter and does **not** set the proxy flag. Child stdio and foreground console/process group are inherited; the wrapper survives Ctrl-C so it can remove the run registration and return the child's exit status (128 + signal on Unix).

| Codex | built-in provider: prepend `-c openai_base_url="<local>"`; selected custom provider: invocation-only `-c model_providers.<id>.base_url="<local>"`, preserving its configured upstream and credentials; selected profile and CLI endpoint overrides are honored |
| Gemini | `GOOGLE_GEMINI_BASE_URL` plus separate `CODE_ASSIST_ENDPOINT` route to Code Assist |
| pi / omp | temporary `-e <state>/proxy/runs/<run>/provider.js`; `registerProvider(provider, {baseUrl})` only, plus the current in-memory model object's URL; no `setModel` or auth override |
| OpenCode | merge V1 `provider.*.options.baseURL` and V2 `providers.*.settings.baseURL` into invocation-local `OPENCODE_CONFIG_CONTENT`, preserving its other fields |
| Qwen | `OPENAI_BASE_URL`, `OPENAI_API_BASE`; documented OpenAI-compatible/API-key route (legacy OAuth is discontinued) |
| Kimi Code 2.x | only existing `KIMI_MODEL_NAME` + `KIMI_MODEL_API_KEY` environment-model mode: replace `KIMI_MODEL_BASE_URL`, preserving the existing model, provider type and key; config-file aliases are refused |
| Grok | `GROK_MODELS_BASE_URL`, `GROK_XAI_API_BASE_URL`, and `GROK_CLI_CHAT_PROXY_BASE_URL`; the auxiliary chat endpoint retains its separate upstream; `[proxy.upstream].openai` overrides the default xAI upstream |
| Copilot | `COPILOT_OTEL_FILE_EXPORTER_PATH=<state>/agents/copilot/otel.jsonl`; supported legacy BYOK env routing additionally overrides `COPILOT_PROVIDER_BASE_URL` without changing provider type/auth; registry-based BYOK remains native OTel |

`$STATE/proxy.json` contains PID, port, start timestamp, and binary version. `$STATE/proxy/runs/<128-bit-random-run>.json` contains the wrapper PID, agent, non-secret upstream URLs and inherited metadata. Unknown/expired run capabilities are rejected. The pi/omp asset registers fixed upstreams under internal `/<protocol>/__provider/<provider>/` routes; clients cannot name arbitrary upstream URLs. Upstream URLs containing credentials, query strings, or fragments are rejected rather than persisted. Run JSON and temporary extensions are removed on normal/interrupt exit; stale registrations are reclaimed by the daemon. The daemon exits after its configured idle timeout only when no requests or live runs remain.
`$STATE/proxy` and `$STATE/proxy/runs` are created and secured as mode `0700` on Unix before registration, including existing directories, so other local users cannot enumerate capability filenames. Windows inherits the plugin-state directory's owner-only ACL; this wrapper does not weaken or replace that ACL.

HTTP methods, request bodies, streaming response chunks, status and end-to-end header values pass through unchanged. Host is changed to the fixed upstream authority, as required by HTTP. HTTP requests replace any client `accept-encoding` value with `identity`, so upstreams return plaintext JSON/SSE for observation; response bytes and headers still pass through unchanged. WebSocket handshakes do not change compression negotiation. Transport framing is managed by Hyper. WebSocket Upgrade handshakes retain keys/auth/beta/account headers, and the upgraded stream is copied byte-for-byte, including original masked, fragmented, binary and control frames. Observation never controls forwarding.

One `source=proxy`, `log_type=chat` record is emitted per model request, with run ID for Core's flush-time parenting. Parsers handle Anthropic Messages, OpenAI Chat Completions, OpenAI Responses (SSE, JSON and WebSocket), and Gemini/Code Assist JSON and SSE. SSE events accept CR, LF and CRLF delimiters and join multiple `data:` lines before parsing. Anthropic block starts are structural: empty text/tool envelopes never become assistant text or first-token timestamps; tool JSON deltas produce completed content blocks. Codex `generate=false` prewarms are not model spans. Usage preserves unknown versus zero and final cache/reasoning breakdowns; input tokens are the total prompt including cached tokens, with Anthropic's separate cache counts added to its native input. Request input is the first full request and subsequently the newly added message/input/content suffix plus changed system instructions. Status, latency and observed first-token latency are metadata. Only Core caps, scrubs and writes records; request/response authentication headers are never captured.

## Real-agent loopback check

Build with `cargo build --release`, then run `bash scripts/e2e/run_proxy.sh` on Spark (`HRA_BIN` can select another build). It creates only `hra-e2e-proxy`, relocates HOME/XDG/Claude/Codex config, and uses the shared loopback provider and OTLP mocks. Six real prompts exercise Claude Messages SSE, Codex Responses SSE, and Codex Responses WebSocket: text plus harmless echo for each transport. Codex uses a custom mock provider because 0.162.1 forbids overriding built-in provider definitions; `--dangerously-bypass-hook-trust` enables only the freshly installed, locally vetted isolated hooks without writing a trust store.
The canned echo runs with Codex `--sandbox danger-full-access` and `approval_policy="never"` only inside the fresh isolated workspace: Spark's container denies bwrap network-namespace setup even for `echo`. Do not reuse those flags against untrusted/real model responses.

The driver checks six turn traces, nine proxy chats and three echo tools; exact mock usage; no native chat duplicates; parent and herdr metadata; known dummy auth/custom/account/beta header hashes; first/full and subsequent delta request content; native streamed output before the matching provider's final frame; warmup exclusion; outside-herdr native adapter silence; semantic setup/remove restoration; and idle listener exit. Raw provider/body/header hashes, event timestamps, native output timestamps and OTLP bodies remain under `~/.hra-e2e/proxy/run-*`. Unit transport checks additionally compare request bytes and end-to-end header values case-sensitively (header names remain case-insensitive), including repeated headers.

`captured_claude_cache_breakpoint_move_only_emits_new_messages` in `parse.rs` is normalized from Claude Code 2.1.296 requests captured 2026-10-10 UTC against the shared mock (`run-sVjiVLGk/provider.jsonl`, requests 2→3): only prompt/tool content and cache-breakpoint shape remain, with identifiers scrubbed. Claude removes the first request's `cache_control` when extending history; that metadata move must not re-send the old prompt into the next chat's input. `run::tests` also covers native Codex 0.162.1 custom-provider config and invocation placement, and the Grok/Kimi invocation-only routing contracts.


## Limits

- Mock qualification is not live provider/subscription authentication or real Respan qualification. Tests never use real keys or user configs.
- Kimi Code config-file providers cannot be redirected per invocation. `run kimi` refuses that mode rather than moving credentials or suppressing native chats; its native adapter already records per-step usage. With an existing `KIMI_MODEL_*` environment model, the wrapper changes only the endpoint. Do not pass `-m`/`--model`, which would select a config-file alias instead.
- Model protocols outside Anthropic/OpenAI/Gemini are not translated. Provider policy/config precedence can defeat an environment override (especially Qwen custom registries, OpenCode OAuth rewrites, Grok policy pins). Grok explicit per-model `base_url` overrides cannot be redirected without editing config: its `GROK_CONFIG` overlay forbids network redirection. Use its native adapter for that configuration.
- pi/omp routing observes the selected model at session start and before each user agent run. Auxiliary calls using unrelated, independently cached model objects may require another native adapter source. The extension changes only the live model URL and provider registry in memory.
- Capture parsing is bounded to 8 MiB per JSON/SSE event/WebSocket message and request copy; content text is bounded to the capture ceiling, and Core alone applies the configurable field cap and scrubbing. Oversized/malformed observations lose details, not traffic. Full upstream request/response bytes remain untouched. WebSocket compressed messages are forwarded but not parsed; current Responses traffic does not require negotiated compression.
- Timings are local proxy wall-clock observations, not provider server timings. No tokens or model identity are invented for malformed/unknown bodies. No count-token, model discovery, health or OAuth helper request is mislabeled as model generation.
